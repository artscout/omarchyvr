# Lessons and pitfalls (2026-10-14)

Mistakes we made while running the stack by hand, and what a launcher or GUI must do so nobody makes them again.
It goes with [INVENTORY.md](../docs/INVENTORY.md) (components, commands, history) and [../STATUS.md](../STATUS.md).

## Execution order and exclusivity
| # | Pitfall (what happened) | Rule for the GUI / launcher |
|---|---|---|
| 1 | Second Monado failed with `monado-service is already running`: the previous run was still exiting. | Before any start, wait until `pgrep -x monado-service` is empty (with a timeout and a clear message). Stop only with `omarchyvr vr stop --grace 30` / `omarchyvr desk stop`, never `pkill -f`; kill by PID only. |
| 2 | 6DoF got no camera: `/dev/video0: Device or resource busy` (a stalled earlier run held it). Only ONE process can stream the cameras. | Preflight `fuser /dev/video*`. Any mode where more than one consumer needs the cameras (6DoF + passthrough, hands, controller tracking, recording) starts `pimax-cam broker` first and every consumer uses `--source broker` / `PIMAX_CAM_SOURCE=broker`. Stop the broker last. |
| 3 | The eye tracker can be opened by one process only. | `pimax-eye watch` / `pimax-eye ipd` need Monado without `--eye` (or no Monado). The GUI greys these out while desk/VR runs with eye tracking, or offers to restart desk mode without `--eye`. |
| 4 | Camera view invisible: Monado shows the main app that is active; a helper client (pose printer) connected later and took the display. | Only one main OpenXR app. Helpers must be `XR_EXTX_overlay` sessions (`POSECLI_OVERLAY=1`). Start the main app first. |
| 5 | Headset black although the app was FOCUSED: `run_slam.sh` started Monado without the launcher's compositor env. | Every Monado start uses the one env builder in `rust/omarchyvr-tools/src/vr/config.rs` (`XRT_COMPOSITOR_DESIRED_MODE=2` for 72 Hz / 3 for 90 Hz, `PIMAX_FPS`, `XRT_COMPOSITOR_WAYLAND_CONNECTOR=DP-1`, `XRT_COMPOSITOR_FORCE_WAYLAND_DIRECT=1`, `XRT_COMPOSITOR_FORCE_NVIDIA=0`). Never hand-roll it. |
| 6 | `omarchyvr desk start --6dof` ran 3DoF only: the merged build had `PIMAX_CAM=OFF`. The launcher's check (strings in the binary) passed anyway. Log: `PIMAX_SLAM set, but Monado was built without -DPIMAX_CAM=ON`. | Check `PIMAX_CAM:BOOL=ON` in the build's `CMakeCache.txt` (and grep the log for "built without -DPIMAX_CAM=ON" after start). Offer "reconfigure + rebuild" (`cmake -DPIMAX_CAM=ON . && ninja` in the build dir). |
| 7 | Every Monado relink drops `cap_sys_nice` (GPU priority); runs then stutter or fail the priority request. | After any build, `getcap <build>/src/xrt/targets/service/monado-service` must show `cap_sys_nice=ep`; otherwise show the exact `sudo setcap cap_sys_nice+ep ...` with a pkexec button. Check every build the GUI can start (`~/.local/lib/omarchyvr/monado` main, plus any build set in `paths.toml`). |
| 8 | Replacing `~/.local/bin/omarchyvr` while desk mode runs. | Install the launcher only when nothing runs (`cargo build --release -p omarchyvr-tools && install -m755 target/release/omarchyvr ~/.local/bin/omarchyvr`). |

## Play Steam VR games
1. Once for all games: Ready > "Steam set up for VR games" > Fix (`omarchyvr vr steam-setup on`), then quit and start Steam once (row 27). Fallback for a Steam started some other way, per game: Steam > game > Properties > General > Launch Options: `PRESSURE_VESSEL_IMPORT_OPENXR_1_RUNTIMES=1 %command%` (the app's Steam card shows the line). Then start desk/VR in the app and press Play in Steam. The start points the OpenXR runtime link at the Monado build in use and puts xrizer back in `~/.config/openvr/openvrpaths.vrpath`.
2. `omarchyvr vr steam-options` prints that line; while the runtime link does not point at the build it adds `XR_RUNTIME_JSON=...`.
3. If a game offers SteamVR or OpenXR, either works with the launch option; SteamVR mode (xrizer) is the default (row 23).
