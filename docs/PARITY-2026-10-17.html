Reinstall parity, 2026-10-17

The old lab install (~/pimax-re) worked end to end on 2026-10-16. After a clean uninstall and a reinstall from omarchyvr, Work failed three times in a row. This page lists every input a Work or Play start reads, where the lab had it, where omarchyvr reads it, and what a clean install does with it now.

Rule since this change. Your own data always wins: the uninstaller keeps it, the import brings it back from older places on the PC, or the headset gives it. Without it, the shipped Pimax Dream Air reference stands in (the project headset's own Windows calibration, serials scrubbed; user decision "approve shipping calibrations"), and every start and the app say which is in use. No start waits for a still headset. In Work only WayVR is required.

What failed, and why (blockers first)

  1. "omarchyvr-slam export: no calibration file found" (13:16, 13:18). The factory calibration was reset with the settings, and the lab had kept it in its own tree. Kept and read from the headset by the Room setup change; now also the shipped reference when none of your own exists, and imported from Pimax's Windows data.
  2. "timed out waiting for the gyro calibration (service left running)" (13:27). The real cause was IMU data that stopped flowing (camera frames all "older than last by 0 ns": a frozen IMU clock), not the reset gyro cache: the driver falls back to the cache, or zero, after 3 s of samples. The missing cache did make the next start (13:29) track with a zero bias. Now: no start waits for a still headset, the cache always holds a bias, and a start without motion data stops Monado again.
  3. pimax-ctrltrack panicked at track.rs:47 (13:29): the controller models existed only in the lab's copy of Pimax's Windows data. The whole Work start failed and left Monado running. Now: imported, a shipped reference, an error instead of a panic, and Work starts without optical controller tracking if the tracker still cannot start.
  4. Two hidden blockers the audit found, which hit any PC without the lab's ~/src (or this PC after --remove-lab-builds): Basalt's base VIO config (every 6DoF start), and libopenvr_api.so for WayVR (every Work start). Both fixed.

What changed

  • Shipped reference in rust/pimax-device/devices/dream-air/reference/: factory XML (deviceUID="reference"), controller models left/right, the tuned lens profile, a typical gyro bias. Compiled into pimax-cam, pimax-ctrltrack, pimax-lens, omarchyvr-config; installed with the data copy. PIMAX_NO_REFERENCE=1 turns it off. The leak scanner allows exactly these files by path and hash and refuses calibration content anywhere else.
  • Import from the previous install: omarchyvr import-previous (--status, --dry-run), run by install.sh and by the app by itself when its checks find more (nothing running). It reads the old places, the lab tree and its Windows data, a mounted shared drive, and the uninstaller's backups (a small streaming tar reader; never ai.toml), never overwrites, writes mode 600, and records what it looked at.
  • Uninstaller: keeps the device data (also from the older places), --reset-calibration to drop it, and no ai.toml in the settings tar.
  • Gyro: PIMAX_BIAS_TIMEOUT_MS=200 in the one env builder (Monado and the SteamVR driver), the cache seeded with the saved or default bias, the SLAM export seeded with the same value; plain start lines.
  • Work: optional parts degrade, a failed start stops what it began; pimax-ctrltrack returns errors; every start prints "headset data: calibration = ..., controller models = ..., lens = ..., gyro = ...".
  • App: Checks items "Your previous install" (with Fix), "Controller models" (found / reference / import) and "Headset data"; the Room setup tile and the start gate use the reference; a help entry.
  • Installer: libopenvr_api.so next to WayVR, the device descriptors in the data copy, the import step.

Remaining

  • IPD OXR_DEBUG_IPD_MM is read by each OpenXR client, not by monado-service: Steam games on Monado render at 63 mm (as in the lab). A driver-side IPD in the Monado fork would close it.
  • headset's own calibration the setup does not read it by itself yet; the reference stands in until Room setup reads it (on this PC your own file is in place).
  • XDG some readers follow XDG_CONFIG_HOME, others only $HOME/.config (the same on a normal desktop).
  • omarchyvrd in executing mode runs the room, sound and local-AI start steps twice (found by the audit, not changed).
  • games every install writes "Games run with: SteamVR" again (the installer's choice, not changed).
  • install nothing here is installed yet: the main thread installs a clean build of the merged commit between sessions.
